## 1. 개요

처음 들어온 사용자에게 홈 화면 위에서 해달이 말풍선으로 안내한다.
설명만 하지 않고, 출석·낚싯대 강화·해먹 넓히기·퀴즈를 **광고 없이 한 번씩 직접 해 보게** 한다.
마지막에 **첫 선물로 해먹을 가득 채워 주고**, 사용자가 **광고를 보고 창고에 저장**하면 튜토리얼이 끝난다.
끝까지 마치면 **해달 친구가 24시간** 함께 낚시한다.

이와 함께 해달 친구 규칙을 바꾼다. 출석 7일차 친구도 자정에 떠나지 않고 **온 때부터 24시간** 머문다 (5장).

### 범위

| 포함 | 제외 (후속) |
|---|---|
| 첫 방문 튜토리얼 (홈, 10단계 + 마무리), 퀴즈·룰렛 화면을 처음 열 때의 짧은 안내 | 기능 이름 변경 (빨리 낚기, 양동이 키우기 등) |
| 튜토리얼 체험 보상: 낚싯대 강화, 해먹 넓히기 (홈), 연습 퀴즈 (퀴즈 화면) — 광고 없이, 종류별 한 번 | 물고기 단위 변경 (g 단위) |
| 첫 선물: 해먹을 지금 용량까지 채움 (최대 1마리, 한 번) | 토스 포인트 전환 |
| 완료 보상: 해달 친구 1명 24시간 (한 번) | 튜토리얼 안의 룰렛 체험 (설명만 한다) |
| 해달 친구 규칙 변경: 자정까지 → 온 때부터 24시간 | 낚싯대·해먹·미끼의 24시간 유지 (자정 초기화 그대로) |
| 건너뛴 사용자를 위한 기능별 첫 안내, 다음 날 자정 초기화 안내 | 홈 화면 배치 변경 |
| 튜토리얼이 대신하는 홈 상시 설명 문구 정리 | |

### 목표

- "해달이 잡는다 → 해먹에 쌓인다 → 창고에 옮긴다 → 토스 포인트로 받는다"를 이해한다.
- 출석, 낚싯대 강화, 해먹 넓히기를 직접 눌러 보고, 누르면 무엇이 오르는지 눈으로 본다.
- 퀴즈·룰렛은 홈에서 한 줄로만 알리고, 그 화면을 처음 열 때 화면 안에서 알려준다 (2026-11-16 팀 피드백: 홈 튜토리얼이 길다).
- 광고는 마지막 저장에서 **한 번만** 본다. 앱을 이해한 뒤, 선물을 받는 맥락에서 본다.
- 끝나면 해달 친구가 장면에 바로 나타나, 첫날부터 더 빨리 낚는 걸 본다.
- 전체 1분 30초 안쪽.

## 2. 보상

| 단계 | 보상 | 광고 | 횟수 | 1명당 비용 |
|---|---|---|---|---|
| 5. 출석 | 낚싯대 +1단계 (원래 출석 보상) | 없음 (원래 없음) | 원래 출석 규칙 | 기존과 같음 |
| 6. 낚싯대 강화 체험 | 낚싯대 +1단계, 오늘 자정까지 | 없음 | 사용자당 한 번 | |
| 7. 해먹 넓히기 체험 | 해먹 +1단계, 낚싯대 +1단계, 오늘 자정까지 | 없음 | 사용자당 한 번 | 세 체험 합쳐 0.05원 안쪽 |
| 퀴즈 화면 연습 퀴즈 | 낚싯대 +1단계, 오늘 자정까지 | 없음 | 사용자당 한 번 | |
| 9. 첫 선물 | 해먹을 지금 용량까지 채움, 최대 1마리 | 없음 | 사용자당 한 번 | 튜토리얼대로면 약 0.62원 |
| 끝. 완료 보상 | 해달 친구 1명, 받은 때부터 24시간 | 10단계 저장 광고를 본 뒤 | 사용자당 한 번 | 최대 0.9원 (하루 2~3번 들어오면 0.1~0.2원) |

정한 이유:

- **체험 보상은 쿨타임을 시작하지 않는다.** 기존 광고 강화 API를 쓰면 20분(낚싯대)·60분(해먹) 쿨타임이 걸려, 튜토리얼이 끝난 직후 광고 버튼이 잠긴다. 튜토리얼 전용 API로 주고 `ad_rod_enhanced_at`, `ad_hammock_expanded_at`은 건드리지 않는다.
- **종류별 한 번은 서버가 지킨다.** 서버는 광고를 확인하지 않으므로(광고는 웹이 띄운다), 막지 않으면 튜토리얼 API로 광고 없이 계속 강화할 수 있다.
- **해먹 넓히기 체험도 하루 최대 단계(10단계) 안에서 센다.** 그날 광고로 넓힐 수 있는 횟수가 하나 줄 뿐, 하루 최대치는 그대로다.
- **첫 선물은 지금 용량까지 채운다.** 7단계에서 해먹이 넓어져(0.56 → 0.616마리) 고정량 0.56마리로는 가득 차지 않기 때문이다. 해달 친구가 이미 와 있는 테스트 계정 같은 경우를 막으려고 최대 1마리로 묶는다.
- **첫 선물은 넘친 양(`overflow_nano_fish`)에 넣지 않는다.** 그래서 10단계에서 저장할 때 다시 잡아오기 창이 뜨지 않는다.
- **완료 보상은 첫 선물을 받은 뒤에만 받을 수 있다.** 서버는 사용자가 광고를 끝까지 봤는지 확인할 수 없지만, 한 번뿐이고 0.9원이라 막지 않는다.
- **룰렛은 체험시키지 않는다.** 랜덤 보상이라 앱인토스 정책을 아직 확인하지 못했고(`bait-roulette.md`), 튜토리얼에서 늘 같은 결과가 나오게 하면 실제 확률과 달라 오해를 산다.
- 수지는 2-1에 적었다.
- 선물한 물고기와 친구가 잡은 물고기도 저장할 때 창고 원장(`warehouse_ledger`, `STORE`)에 들어가므로 월 발행 총액 보고에 빠지지 않는다.

### 2-1. 수지 (2026-11-16, 해달 친구 해먹 용량 +10% 기준)

해달 친구 해먹 용량을 +50%에서 +10%로 줄였다 (속도 +50%는 그대로). 친구가 와도 해먹이 금방 차서,
자주 비우는 사람만 친구 몫을 다 받는다. 같은 방문 패턴의 일반 사용자와 비교해 튜토리얼 사용자가 더 받는 양이다
(튜토리얼을 20시에 마침, 48시간 동안, 방문마다 저장).

| 방문 패턴 | 친구·체험으로 더 받는 양 (+50% 때) | (+10%, 지금) | 첫 선물 포함 비용 | 튜토리얼 광고 수익 (1회 × 1.5원) | 우리 손익 |
|---|---|---|---|---|---|
| 하루 2번 | 0.56원 | 0.11원 | 0.73원 | 1.5원 | +0.77원 |
| 하루 3번 | 0.68원 | 0.23원 | 0.85원 | 1.5원 | +0.65원 |
| 하루 5번 | 0.85원 | 0.63원 | 1.24원 | 1.5원 | +0.26원 |
| 해먹을 한 번도 넘치지 않게 비움 (최대) | 0.91원 | 0.91원 | 1.53원 | 1.5원 | -0.03원 |

- 광고 수익은 튜토리얼 마지막 저장 광고 1회만 셌다 (광고 단가 1.5원은 노션 PM 페이지 가정). 체험 강화로 오른 속도 때문에 늘어나는 광고는 넣지 않았다.
- 최대치(-0.03원)는 15분마다 들어와 비우는 경우라 현실적이지 않다. 하루 2~5번 들어오는 사용자는 튜토리얼 하나로 0.3~0.8원 남는다.
- 출석 7일차 해달 친구도 같은 규칙이라, 7일차에 하루 2~3번 들어오는 사용자의 친구 몫도 함께 줄어든다. 월 예산 최악값(해먹을 늘 비우는 경우)은 해먹 용량과 상관없어 그대로다.

## 3. 튜토리얼 흐름

실제 홈 화면 위에 어두운 막을 깔고, 안내할 부분만 밝게 비춘다. 해달 말풍선은 한 번에 한 줄이다.
오른쪽 위에 **건너뛰기**를 항상 둔다.

```
1. 해달 낚시      "편하게 쉬다 오세요 / 물고기는 제가 계속 잡을게요!"       다음
     |
2. 양동이 게이지  "쉬는 동안 잡은 물고기는 / 여기 양동이에 쌓여요"            다음
     |
3. 저장 버튼      "해먹이 차면 이 버튼으로 창고에 옮겨요"                     다음 (설명만)
     |
4. 내 창고        "창고에 모은 물고기는 토스 포인트로 받을 수 있게 준비하고 있어요"   다음
     |
5. 출석 체크      "매일 출석하면 낚싯대가 강화돼요. 7일째엔 해달 친구가 와요"   출석 버튼을 누른다
     |
6. 낚싯대 강화    "이번엔 광고 없이 강화해 드릴게요"                          버튼을 누른다
     |
7. 해먹 넓히기    "이번엔 광고 없이 넓혀 드릴게요"                            버튼을 누른다
     |
8. 퀴즈·룰렛 버튼 "O/X 퀴즈와 미끼 룰렛도 낚싯대를 빠르게 해줘요. 처음 열면 알려드릴게요"  다음 (설명만)
     |
9. 첫 선물        해먹이 가득 차는 연출 "첫 선물로 해먹을 가득 채워뒀어요!"     다음
     |
10. 저장 버튼     "광고를 보고 창고에 옮겨보세요"                             광고 보고 저장
     |
끝. 해달 장면     해달 친구 등장 "제 친구가 왔어요! 내일 {시각}까지 함께 낚시해요"   시작하기
```

### 단계별 처리

| 단계 | 누르면 | 결과 말풍선 (잠깐) |
|---|---|---|
| 5 | 기존 출석 체크 (`POST /attendance/check-in`) | "낚싯대가 1단계 강화됐어요" |
| 6 | `POST /tutorial/rewards/ROD` | "낚싯대가 1단계 강화됐어요" |
| 7 | `POST /tutorial/rewards/HAMMOCK` | "해먹이 넓어지고 낚싯대도 강화됐어요" |
| 9 | `POST /tutorial/rewards/GIFT` (단계에 들어갈 때) | 해먹 게이지가 가득 차는 연출 |
| 10 | 보상형 광고 → 기존 저장 (`POST /fishing/store`) → `POST /tutorial/complete` | 친구 등장 (마무리 단계로) |

- 1~4단계의 저장 버튼과 창고는 비추고 설명만 한다. 이때 해먹은 거의 비어 있다.
- 5단계: 출석 뒤 나오는 '광고 보고 보상 한 번 더 받기' 버튼은 튜토리얼 동안 누를 수 없게 막아 둔다 (끝난 뒤에는 그대로 쓸 수 있다).
  오늘 이미 출석했으면(테스트 계정 등) 출석 카드를 비추고 다음 버튼만 둔다.
- 6·7단계: 홈 위쪽의 실제 버튼을 비추고, 튜토리얼 동안에만 버튼 글자를 "광고 없이 강화하기", "광고 없이 넓히기"로 바꾼다. 누르면 광고 대신 튜토리얼 API를 부른다.
- 8단계: 홈 아래쪽 퀴즈·룰렛 바로가기 두 버튼을 함께 비추고 한 줄만 말한다. 자세한 안내는 3-1의 화면 안내가 맡는다.
- 10단계: 홈의 저장 버튼("광고 보고 창고에 저장하기")을 그대로 쓴다. 저장 안내(토스트)는 띄우지 않고 마무리 단계로 넘어간다.
  광고를 쓸 수 없는 환경이거나 광고를 불러오지 못하면, 홈과 똑같이 광고 없이 저장하고 끝낸다.
  광고를 끝까지 보지 않고 닫으면 저장하지 않고 10단계에 머문다. 다시 누르거나 건너뛸 수 있다.
- 마무리: 시각은 완료 응답의 `otterFriendUntil`이다 (예: "내일 오후 3:04"). 완료 요청이 실패하면 친구 문구 대신 "이제 해달과 함께 낚시를 시작해요"를 보여준다.
- 4단계 문구는 토스 포인트 전환이 나오면 "창고에 모은 물고기는 토스 포인트로 받을 수 있어요"로 바꾼다. ADR-0003에 따라 '출금', '인출', '환전'은 쓰지 않는다.

### 3-1. 퀴즈·룰렛 화면 안내

그 화면을 처음 열 때 한 번, 홈과 같은 비추기 막과 해달 말풍선으로 띄운다. 오른쪽 위에 건너뛰기를 둔다.

```
O/X 퀴즈 화면 (첫 문제를 비춘다)
1. "매일 해달 퀴즈 3문제가 나와요. 맞히고 광고를 보면 오늘 낚싯대가 강화돼요"   다음
2. "틀려도 광고를 보면 한 번 더 풀 수 있어요"                                   다음
3. 말풍선 안 연습 문제 "해달은 잠잘 때 서로 손을 잡고 자요"                     O 또는 X
   → "정답은 O예요. ... 이번엔 광고 없이 낚싯대를 강화해 드렸어요"              시작하기

미끼 룰렛 화면 (설명만)
1. 룰렛판      "하루 한 번 룰렛을 돌려 오늘의 미끼를 뽑아요"                    다음
2. 효과 보기   "미끼마다 빨라지는 정도가 달라요. 여기서 확인할 수 있어요"        다음
3. 돌리기 버튼 "뽑은 뒤 광고를 보고 미끼를 달면 오늘 자정까지 더 빨리 낚아요"     시작하기
```

- 연습 퀴즈는 `POST /tutorial/rewards/QUIZ`로 한 번만 강화한다. 오늘의 퀴즈 3문제와 따로이고, O·X 어느 쪽이든 강화한다.
  이미 받았으면 연습 단계 없이 설명만 한다.
- 연습 퀴즈 보상은 홈 튜토리얼을 마친 뒤에도 받는다 (보통 홈 튜토리얼을 마친 뒤 퀴즈 화면을 연다). 건너뛴 사람은 받지 못한다.
- 본 기록은 브라우저 저장소에 둔다 (보상은 서버가 한 번만 준다). 저장소를 쓸 수 없으면 띄우지 않는다.
- 홈 튜토리얼을 건너뛴 사람(`SKIPPED`)에게는 화면 안내도 띄우지 않는다.
- 룰렛은 앱인토스 정책 확인 전에는 운영에 내보내지 않는다(`bait-roulette.md`). 룰렛을 숨기면 이 안내도 함께 숨는다.

### 언제 보여주나

- `GET /tutorial/me`의 `status`가 `NOT_STARTED` 또는 `IN_PROGRESS`인 사용자가 홈에 들어왔을 때.
- 중간에 앱을 닫았다가 다시 들어오면(`IN_PROGRESS`) 아직 받지 않은 첫 보상 단계부터 이어서 한다. 이미 받은 보상은 다시 주지 않는다.
- 건너뛰기를 누르면 `POST /tutorial/skip`으로 기록하고(`SKIPPED`), 다시 뜨지 않는다. 이미 받은 체험 보상과 선물은 그대로 둔다. 완료 보상은 없다.
- 마치면(`DONE`) 다시 뜨지 않는다. 상태는 서버에 있으므로 기기를 바꿔도 같다.

## 4. 기능별 첫 안내

튜토리얼을 건너뛴 사용자는 기능 설명을 못 본다. 그 기능을 처음 마주칠 때 한 번만 짧게 띄운다 (해달 말풍선).
튜토리얼에서 이미 지나간 단계는 본 것으로 기록해 다시 띄우지 않는다.

| 언제 | 문구 | 튜토리얼 단계 |
|---|---|---|
| 첫 출석 체크 직후 | "7일 연속 오면 해달 친구가 와서 하루 동안 함께 낚시해요" | 5 |
| 낚싯대 강화 버튼을 처음 누를 때 (광고 전) | "광고를 보면 오늘 자정까지 낚싯대가 강화돼요" | 6 |
| 해먹 넓히기 버튼을 처음 누를 때 (광고 전) | "광고를 보면 오늘 자정까지 해먹이 커져요" | 7 |
| 퀴즈·룰렛 화면을 처음 열 때 | 3-1의 화면 안내 | 3-1 |
| 튜토리얼을 마치거나 건너뛴 다음 날 처음 들어올 때 | "강화는 매일 자정에 처음으로 돌아가요" | 모두에게 |
| 해먹이 처음 가득 찼을 때 | 따로 띄우지 않는다. 저장 직후의 다시 잡아오기 창으로 충분하다 | |

- 보상이 걸려 있지 않아서 본 기록은 브라우저 저장소(`localStorage`)에 둔다. 기기를 바꾸면 한 번 더 볼 수 있지만 문제없다.
- 저장소를 쓸 수 없는 환경(읽기·쓰기에서 예외)에서는 안내를 띄우지 않는다. 매번 뜨는 쪽보다 안 뜨는 쪽이 낫다.

## 5. 해달 친구 24시간 (규칙 변경)

### 바뀌는 것

| | 지금 | 바꾼 뒤 |
|---|---|---|
| 머무는 시간 | 온 날 KST 자정까지 | 온 때부터 24시간 |
| 밤 11시 58분에 7일차 출석 | 2분 | 다음 날 밤 11시 58분까지 |
| 출석 '광고 보고 2배'로 온 두 번째 친구 | 같은 날 자정까지 | 두 친구 모두 두 번째 친구가 온 때부터 24시간 |
| 튜토리얼 완료 보상 | 없음 | 친구 1명, 24시간 |
| 낚싯대·해먹·미끼 | 자정 초기화 | 그대로 자정 초기화 |

- 친구가 있는 동안 새 친구가 오면 인원은 1명 늘고(최대 2명) 떠나는 시각은 **새 친구가 온 때부터 24시간**으로 함께 미룬다.
  친구마다 떠나는 시각을 따로 두지 않아서 상태가 단순하다. 먼저 온 친구가 조금 더 머무는 정도의 차이다.
- 친구가 떠나면 해먹 용량도 줄어든다. 이미 담긴 물고기는 줄이지 않고, 용량 아래로 내려갈 때까지 더 담지 않는다 (지금 자정에 용량이 줄 때와 같다).
- `OTTER_FRIEND_POLICY.MAX_PER_DAY`(2명)는 "동시에 함께 있는 최대 인원"으로 뜻이 바뀐다. 이름을 `MAX_FRIENDS`로 바꾸고 `STAY_HOURS: 24`를 더한다.

### 상태 (`fishing_states`)

| 칸 | 지금 | 바꾼 뒤 |
|---|---|---|
| `otter_friend_date` (`date`) | 친구가 오는 KST 날짜 | 쓰지 않는다 (다음 마이그레이션에서 지움) |
| `otter_friend_until` (`timestamptz NULL`, 신규) | | 친구가 떠나는 시각 |
| `otter_friend_count` (`smallint`) | 그날 친구 수 | `otter_friend_until` 전까지 함께 있는 친구 수 |

### 정산 (`lib/settle-hammock.ts`)

지금은 속도가 자정에만 바뀌어 정산 구간이 최대 두 개다. 친구가 자정과 상관없이 떠나므로 **친구가 떠나는 시각**도 경계가 된다.

```
settledAt ──[그날 보너스 + 친구]── (자정 또는 친구 떠남) ──[…]── (나머지 하나) ──[…]── now
```

- 구간 경계: `settledAt` 다음 자정, `otter_friend_until` 중 `settledAt`과 `now` 사이에 있는 것. 그래서 구간은 최대 세 개다.
- 각 구간의 보너스: 낚싯대·해먹·미끼는 `settledAt`과 같은 날(자정 전)에만, 친구는 `otter_friend_until` 전에만 붙는다.
- `predictHammockFullAt`도 같은 구간으로 계산한다. 친구가 떠나는 시각을 넘기면 속도가 떨어진 뒤의 가득 차는 시각을 계산한다.
- 친구는 최대 24시간이라 `settledAt` 뒤로 자정을 두 번 넘겨 남아 있을 수 없다. 두 번째 자정 뒤는 늘 보너스 없음이다.

### 화면

| 위치 | 지금 | 바꾼 뒤 |
|---|---|---|
| 오늘의 강화 시트 설명 | "오늘 자정까지 적용되는 강화예요. 자정이 지나면 모두 초기화돼요." | "낚싯대·미끼·해먹은 오늘 자정까지, 해달 친구는 온 때부터 24시간 함께해요." |
| 오늘의 강화 시트 해달 친구 행 (함께 있을 때) | 출석으로 온 친구 설명 | "{떠나는 시각}까지" (예: "내일 오후 3:04까지") |
| 출석 7일차 버튼 | "출석하고 해달 친구 부르기" | 그대로 |

## 8. API

튜토리얼은 새 모듈 `modules/tutorial`에 둔다. 출석·퀴즈 모듈처럼 자기 트랜잭션 안에서 `FishingService`의 공개 메서드를 불러 해먹을 바꾼다.

### `GET /tutorial/me` (신규)

```ts
{
  status: 'NOT_STARTED' | 'IN_PROGRESS' | 'DONE' | 'SKIPPED',
  claimed: { ROD: boolean, HAMMOCK: boolean, QUIZ: boolean, GIFT: boolean },
}
```

- `NOT_STARTED`: 기록이 없음. `IN_PROGRESS`: 보상을 하나 이상 받았고 끝내거나 건너뛰지 않음.

### `POST /tutorial/rewards/:kind` (신규)

`kind`는 `ROD`, `HAMMOCK`, `QUIZ`, `GIFT` 중 하나다.

1. 튜토리얼 행을 잠근다 (없으면 만든다). 이미 끝냈거나 건너뛰었으면 409 "이미 끝난 튜토리얼이에요".
   단 `QUIZ`는 퀴즈 화면에서 받으므로 끝낸 뒤에도 주고, 건너뛰었을 때만 409다.
2. 그 종류를 이미 받았으면 409 "이미 받은 보상이에요".
3. 같은 트랜잭션에서 보상을 준다.

| kind | 부르는 `FishingService` 메서드 | 내용 |
|---|---|---|
| `ROD` | `enhanceRod(userId, 1, manager, now)` (기존) | 낚싯대 +1단계 |
| `HAMMOCK` | `expandHammock(userId, manager, now)` (신규, 쿨타임 없음) | 해먹 +1단계, 낚싯대 +1단계. 이미 최대 단계면 낚싯대만 |
| `QUIZ` | `enhanceRod(userId, 1, manager, now)` (기존) | 낚싯대 +1단계 |
| `GIFT` | `fillHammock(userId, maxFish, manager, now)` (신규) | 해먹을 지금 용량까지 채움, 최대 1마리 |

4. 그 종류를 받은 시각을 적고, 응답으로 최신 낚시 현황(`FishingStatusResponse`)을 돌려준다.

### `POST /tutorial/complete` (신규)

1. 튜토리얼 행을 잠근다. 첫 선물(`GIFT`)을 받지 않았으면 409 "튜토리얼을 먼저 진행해 주세요". 이미 끝냈거나 건너뛰었으면 409.
2. `FishingService.summonOtterFriend`로 해달 친구를 한 명 부르고(5장 규칙), `completed_at`을 적는다.
3. 응답: 최신 낚시 현황 (`otterFriendUntil` 포함).

### `POST /tutorial/skip` (신규)

`skipped_at`을 적는다. 이미 끝냈으면 그대로 둔다 (200).

### `GET /fishing/me` (기존)

응답에 `otterFriendUntil: string | null`(친구가 떠나는 시각, ISO 8601)을 더한다.
`otterFriendActive`, `otterFriendCount`는 지금 시각에 함께 있는 친구로 계산한다.

### 해달 친구 부르기 (`FishingService.summonOtterFriend`, 변경)

출석 7일차, 출석 광고 2배, 튜토리얼 완료가 모두 이 함수를 쓴다.
`otter_friend_until`이 지났으면 인원을 0부터 센다. 인원을 1 늘리고(최대 2명), `otter_friend_until`을 지금부터 24시간 뒤로 둔다.

### `POST /fishing/store` (기존, 변경 없음)

10단계는 홈과 같은 저장이다. 광고를 띄우는 건 웹이 정한다.

### 정책값

```ts
// fishing.policy.ts
OTTER_FRIEND_POLICY = { SPEED_BONUS_PERCENT: 50, CAPACITY_BONUS_PERCENT: 10, MAX_FRIENDS: 2, STAY_HOURS: 24 }

// tutorial.policy.ts (해먹 넓히기 체험은 광고 해먹 넓히기와 같은 HAMMOCK_EXPAND_POLICY 를 쓴다)
TUTORIAL_REWARD_POLICY = { ROD_LEVELS: 1, QUIZ_ROD_LEVELS: 1, GIFT_MAX_FISH: 1 }
```

### DB

`user_tutorials` (신규, 사용자당 한 행. 다른 테이블처럼 `id`·`created_at`·`updated_at`을 두고 `user_id`에 유니크 제약)

| 칸 | 타입 | 의미 |
|---|---|---|
| `user_id` | `uuid`, 유니크 | `users.id` (관계는 걸지 않는다) |
| `rod_rewarded_at` | `timestamptz NULL` | 낚싯대 강화 체험 보상을 받은 시각 |
| `hammock_rewarded_at` | `timestamptz NULL` | 해먹 넓히기 체험 보상 |
| `quiz_rewarded_at` | `timestamptz NULL` | 연습 퀴즈 보상 |
| `gift_rewarded_at` | `timestamptz NULL` | 첫 선물 |
| `completed_at` | `timestamptz NULL` | 마친 시각 (완료 보상을 준 시각) |
| `skipped_at` | `timestamptz NULL` | 건너뛴 시각 |

`fishing_states`

| 칸 | 타입 | 의미 |
|---|---|---|
| `otter_friend_until` | `timestamptz NULL` (신규) | 해달 친구가 떠나는 시각 |

- 테이블과 칸을 더하기만 하는 마이그레이션이다. 지금 친구가 있는 행은 `otter_friend_until`을 `otter_friend_date` 다음 날 0시(KST)로 채워, 배포 시점에 와 있던 친구는 원래대로 자정에 떠난다.
- 새 서버는 `otter_friend_date`도 계속 함께 적는다. 배포하는 동안 이전 버전 서버가 같은 DB를 읽어도 깨지지 않게 하기 위해서다. `otter_friend_date`는 다음 배포의 마이그레이션에서 지운다.
- 지금 DB의 사용자(테스트 계정)는 `user_tutorials` 행이 없으므로, 배포 후 처음 들어오면 튜토리얼을 한 번 본다.

| `features/today-boost` | 시트 설명 문구, 해달 친구 행에 떠나는 시각 |

- 튜토리얼 진행 상태(지금 몇 단계인지, 지금 튜토리얼 중인지)는 홈 안의 React 컨텍스트 하나로 버튼들에 내려준다. 버튼마다 따로 상태를 두지 않는다.
- 비추는 위치는 표시한 요소의 `getBoundingClientRect()`로 잡고, 화면 밖이면 먼저 스크롤한다. 화면 크기가 바뀌면 다시 잰다.
- 막은 비춘 영역만 눌리게 한다. 누르는 단계(5, 6, 7, 11)에서는 그 버튼만 눌린다.
- 말풍선은 `role="dialog"`와 `aria-live="polite"`로 낭독기에 읽히게 하고, 버튼은 44px 이상으로 둔다.
- 장면 캔버스(`scene-engine`)는 고치지 않는다. 친구는 이미 있는 `withOtterFriend`로 띄우고, 말풍선은 장면 위에 겹친다.
- 보상 응답이 최신 낚시 현황이므로 바로 화면에 반영한다(게이지, 오늘의 강화 숫자).

## 10. 예외 상황

| 상황 | 처리 |
|---|---|
| 튜토리얼 상태 조회가 실패함 | 튜토리얼을 띄우지 않고 평소 홈을 보여준다. 다음에 들어오면 다시 본다 |
| 체험 보상 요청이 실패함 (네트워크) | "잠시 후 다시 눌러주세요"를 보여주고 그 단계에 머문다. 다음 버튼도 열어 넘어갈 수 있게 한다 |
| 이미 받은 보상 (409, 다른 기기 등) | 그 단계를 받은 것으로 보고 다음 단계로 간다 |
| 오늘 이미 출석함 | 5단계는 출석 카드를 비추고 다음 버튼만 둔다 |
| 5단계에서 출석이 실패함 | 기존 출석 실패 안내를 보여주고, 다음 버튼을 열어 넘어갈 수 있게 한다 |
| 해먹이 이미 최대 단계 (테스트 계정) | 7단계 보상은 낚싯대만 오른다. 결과 말풍선은 "낚싯대가 강화됐어요" |
| 첫 선물 요청이 실패함 | 9단계에 머물고 다시 시도하게 한다. 건너뛸 수 있다 |
| 10단계 광고를 쓸 수 없는 환경 | 홈과 같이 광고 없이 저장하고 끝낸다 |
| 10단계 광고를 끝까지 안 봄 | 저장하지 않고 10단계에 머문다 |
| 10단계 저장이 실패함 | 기존 저장 실패 안내를 보여주고 10단계에 머문다 |
| 완료 요청이 실패함 | 마무리 문구를 "이제 해달과 함께 낚시를 시작해요"로 바꾸고 닫는다. 다음에 들어왔을 때 `IN_PROGRESS`이고 선물을 받았으면 마무리 단계만 다시 띄워 완료를 재시도한다 |
| 중간에 앱을 닫음 | 다음에 들어오면 받지 않은 첫 보상 단계부터 이어서 한다 |
| 건너뛰기 | 받은 보상은 그대로, 완료 보상은 없다. 못 본 기능은 4장의 첫 안내로 알려준다 |
| 작은 화면에서 비출 곳이 화면 밖 | 먼저 스크롤한 뒤 비춘다 |
| 튜토리얼 중 자정이 지남 | 체험 강화는 그날 자정에 풀린다 (평소 강화와 같다). 친구는 24시간이라 영향 없다 |
| 친구가 떠나 해먹 용량이 줄었는데 해먹이 용량보다 많음 | 줄이지 않는다. 저장하면 다시 담기 시작한다 |

## 11. 테스트

- api 튜토리얼: 종류별 한 번만(두 번째는 409), 끝내거나 건너뛴 뒤에는 409, 체험 보상이 쿨타임 시각을 건드리지 않는지, 해먹 최대 단계에서 낚싯대만 오르는지
- api 첫 선물: 지금 용량까지만 채우는지, 1마리를 넘지 않는지, 넘친 양에 넣지 않는지
- api 완료: 선물 전에는 409, 한 번만, 친구 1명과 24시간 뒤 떠나는 시각, 상태가 `DONE`
- api 상태: `NOT_STARTED` → `IN_PROGRESS` → `DONE`/`SKIPPED`, `claimed` 값
- api 해달 친구: 24시간 뒤 떠나는지, 자정을 넘겨도 남는지, 있는 동안 새 친구가 오면 2명이 되고 떠나는 시각이 미뤄지는지, 최대 2명
- api 정산: 친구가 자정 전·후에 떠나는 경우의 구간 계산, 친구가 떠나 용량이 줄 때 물고기를 줄이지 않는지, 가득 차는 시각 예측
- api: 월 예산 테스트(친구 7일, 체험 낚싯대 2단계, 선물 1마리), `otterFriendUntil` 응답, 컨트롤러 연결
- web: 누르는 단계는 성공해야 넘어가는지, 이어서 하기, 오늘 이미 출석했을 때, 10단계 광고 실패·중간 닫기, 건너뛰기, 완료 뒤 친구 등장
- web: 첫 안내가 튜토리얼에서 지나간 단계는 다시 안 뜨는지, 저장소를 쓸 수 없을 때 안 뜨는지
