# 제철 미끼 룰렛 설계

- 상태: 초안 (서버 API만 구현)
- 작성일: 2026-11-10
- 관련: [ADR-0007 낚시 경제](../adr/0007-fishing-economy.md), [fishing.md](./fishing.md)

> ⚠️ **출시 전 정책 확인 필요.** 결과가 확률로 정해지는 랜덤 보상이다.
> 앱인토스 프로모션 가이드는 비게임 앱의 확률형·랜덤 보상을 "1주일 이내, 신규 유입 목적"으로만 허용하고,
> 게임물로 분류되면 확률형 프로모션을 막는다. 룰렛은 토스 포인트를 직접 주지 않고 낚시 속도만 올리지만,
> 물고기가 토스 포인트로 전환되므로 같은 기준이 적용되는지 앱인토스 문의로 확인해야 한다.
> 해먹 넓히기는 같은 이유로 랜덤을 쓰지 않는다 (CLAUDE.md). 답변 전에는 운영에 배포하지 않는다.
> 불가로 답이 오면 같은 구조에서 결과를 날짜별 고정 미끼(달력)로 바꾼다.

## 1. 개요

하루(KST) 한 번 룰렛을 돌려 그달 제철 생선 미끼 하나를 뽑는다. 결과 창에서 보상형 광고를 끝까지 보면
그 미끼의 효과(낚시 속도 +N%)가 그날 자정까지 적용된다. 광고를 보지 않으면 효과는 없고, 그날 안에는 다시 적용할 수 있다.

## 2. 정책값 (`apps/api/src/common/globals/roulette.policy.ts`)

| 등급 | 낚시 속도 | 확률 |
|---|---|---|
| 1 | +1% | 40% |
| 2 | +2% | 30% |
| 3 | +3% | 20% |
| 4 | +5% | 10% |

- 달마다 제철 생선 4종이 있고, 목록 순서대로 1~4등급을 받는다 (`SEASONAL_FISH_BY_MONTH`).
- 생선 목록은 가안이다. 11~1월과 5월만 기사로 확인했고, 나머지 달은 기획 확인이 필요하다.
- 미끼 효과는 낚싯대 강화 단계와 따로 더한다 (낚싯대 하루 최대 단계에 포함되지 않음). 속도 = 100% + 낚싯대 + 해달 친구 + 미끼.
- 월 예산 테스트(`fishing-budget.spec.ts`)는 매일 가장 높은 미끼(+5%)를 적용한 최악의 달로 계산한다.

## 3. 상태

- `roulette_spins`: 사용자·날짜당 한 행. 생선 코드·이름·보너스는 돌린 시점 값으로 저장하고, `applied_at`이 적용 시각이다.
  `(user_id, spin_date)` 유니크 제약이 하루 한 번을 보장한다.
- `fishing_states.bait_bonus_percent`, `bait_date`: 적용한 미끼 효과와 유효 날짜. 다른 보너스처럼 날짜가 오늘일 때만 적용되어 자정 초기화 배치가 없다.

## 4. API

| 메서드 | 경로 | 설명 |
|---|---|---|
| GET | `/api/roulette/today` | 이달의 미끼 4종(보너스·확률), 오늘 결과, `canSpin`, `canApply`, 초기화 시각 |
| POST | `/api/roulette/spin` | 서버 난수로 미끼를 뽑아 저장. 적용은 하지 않는다. 오늘 이미 돌렸으면 409 |
| POST | `/api/roulette/ad-apply` | 광고 시청 후 오늘 결과 적용. 결과가 없으면 404, 이미 적용했으면 409 |

- 결과는 서버 `crypto.randomInt`로만 정한다. 클라이언트가 보낸 결과는 받지 않는다.
- `ad-apply`는 웹이 보상형 광고의 `userEarnedReward`를 받은 뒤에만 부른다.
- 적용 기록과 속도 보너스는 같은 트랜잭션이다 (`FishingService.applyBait`: 정산 → 오늘 미끼 보너스).
- 낚시 현황(`GET /api/fishing/me`)에 `baitSpeedBonusPercent`가 추가됐다.
